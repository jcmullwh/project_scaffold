## Title

Exclude Cookiecutter/Jinja template files from pre-commit ruff/ruff-format hooks

## Problem

Pre-commit ruff and ruff-format hooks attempt to parse Cookiecutter/Jinja template files containing placeholders (e.g., `{{ cookiecutter.* }}`), producing invalid-syntax errors. This can occur even when `pyproject.toml` ruff excludes work for direct CLI runs, because the pre-commit hook configuration may not fully respect or apply those exclusions (and path/glob semantics may differ on Windows).

## User impact

Developers cannot run `pre-commit` successfully (especially on first setup), making the repo appear broken and reducing confidence in making/landing changes.

## Proposed fix

Update `.pre-commit-config.yaml` to add explicit hook-level `exclude:` patterns for ruff and ruff-format that skip Cookiecutter/Jinja template paths (e.g., matching `templates/**/tools/templates/**` and other templated directories), aligning pre-commit behavior with intended ruff exclusions.

## Investigation steps

- Reproduce `pre-commit` failure (preferably on Windows) and capture the exact failing file paths.
- Compare ruff exclusions in `pyproject.toml` with the ruff/ruff-format pre-commit hook configuration to identify mismatch (config not picked up vs path semantics).
- Add/adjust hook-level `exclude:` patterns (and/or ensure the hook uses the intended config) so templated files are skipped.
- Run `pre-commit run --all-files` (or `pre-commit run -a`) on Windows and Unix to validate the exclude regex works cross-platform.

## Success criteria

- `pre-commit run --all-files` (or `pre-commit run -a`) succeeds without ruff/ruff-format syntax errors from Cookiecutter/Jinja template placeholder files.
- Exclusions cover all known templated directories without suppressing checks for real Python source files.
- If CI runs pre-commit, it remains green and consistent across Windows and Unix path semantics.
