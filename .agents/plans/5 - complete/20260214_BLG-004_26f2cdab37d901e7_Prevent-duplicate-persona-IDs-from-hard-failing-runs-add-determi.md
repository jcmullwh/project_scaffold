## Title

Prevent duplicate persona IDs from hard-failing runs; add deterministic validation and clear collision diagnostics

## Problem

When multiple persona files define the same persona ID, persona loading fails (e.g., RunSpecError) and the run aborts before any task work begins. Current behavior blocks runs instead of providing a deterministic, actionable remediation path.

## User impact

Runs fail immediately on first-run/onboarding with a spec/config error unrelated to user intent; users must manually find colliding persona files, harming trust and slowing adoption.

## Proposed fix

Add an upfront, deterministic duplicate-persona-ID validation step in the persona loader (or pre-run validation) that fails with a clear diagnostic enumerating the duplicated ID and all conflicting file paths, plus an explicit remediation suggestion (rename ID or enable a documented namespacing strategy if supported).

## Investigation steps

- Locate the persona discovery/loading codepath and the current duplicate-ID detection/exception type.
- Decide policy: hard-error with guided remediation (recommended) vs optional auto-namespacing behind a flag; document the policy.
- Implement duplicate-ID aggregation so the error lists all duplicates and every conflicting file path (not just the first pair).
- Add a regression test covering duplicate-ID detection and exact/structured error output.

## Success criteria

- Runs never fail with an opaque 'Duplicate persona id' error; the diagnostic lists the duplicated ID and all conflicting persona file paths.
- Duplicate detection is deterministic (stable ordering) and the remediation path is explicit and documented.
- A regression test/validation step fails deterministically when duplicates are introduced.
