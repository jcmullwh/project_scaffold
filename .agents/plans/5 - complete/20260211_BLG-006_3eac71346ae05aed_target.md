# Document Purpose and Maintenance Rules for `.agents/dropins/`

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This plan must be maintained in accordance with `.agents/PLANS.md`.

## Purpose / Big Picture

After this change, maintainers understand what `.agents/dropins/` is for: it is a directory of transplantable "drop-in"
code bundles intended to be copied into other repositories or templates. Because drop-ins are not part of this template
repo's runtime or dependency declaration, tooling like dependency checks and typechecking must exclude them (or be
explicitly configured) to avoid false-positive CI failures.

The outcome is both:

- documentation clarifying purpose and maintenance rules, and
- configuration that makes exclusions explicit and intentional.

## Surprises & Discoveries

- Observation: Ruff currently lints `.agents/dropins` files by default.
  Evidence: `pdm run ruff check . --show-files` includes `.agents/dropins/.../*.py`.

- Observation: Drop-ins include code that depends on third-party libraries not declared as template repo dependencies (for example `packaging`, `build`, `twine`).
  Evidence: `.agents/dropins/monorepo_publish_snapshots/repo_root/tools/monorepo_publish/publish_snapshots.py` imports `packaging`.

- Observation: Deptry treats repo-root `conftest.py` as non-test code and flags dev-only imports (DEP004).
  Evidence: `pdm run deptry .` reported `DEP004 'pytest' imported but declared as a dev dependency` when `conftest.py` imported `pytest`.

## Decision Log

- Decision: Treat `.agents/dropins/` as "asset code" and exclude it from deptry/mypy/ruff in the template repo's quality gates.
  Rationale: Drop-ins are meant to be copied elsewhere with their own dependency model; enforcing template-repo dependency correctness on them creates false positives.
  Date/Author: 2026-02-11 / agent

- Decision: Keep the repo-root pytest config guard (`conftest.py`) free of third-party imports so deptry stays strict and clean.
  Rationale: Deptry scans repo-root Python files; keeping this guard stdlib-only avoids false positives while preserving the early failure behavior for `pytest`.
  Date/Author: 2026-02-11 / agent

## Context and Orientation

Drop-ins live under:

- `.agents/dropins/`

Example drop-in:

- `.agents/dropins/monorepo_publish_snapshots/`: a bundle that can be copied into a monorepo to add snapshot publishing.

Template repo quality tools that can be affected by drop-ins:

- Ruff (`pdm run ruff check .`): lints all Python files under the repo unless excluded.
- Mypy (`pdm run mypy .`): typechecks Python files unless excluded.
- Deptry (`pdm run deptry .`): checks dependency declarations vs imports and can flag drop-in-only imports as missing.

The exclusions are configured in `pyproject.toml`.
