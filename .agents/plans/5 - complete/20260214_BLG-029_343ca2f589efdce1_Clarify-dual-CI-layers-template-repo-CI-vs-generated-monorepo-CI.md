## Title

Clarify dual CI layers (template repo CI vs generated monorepo CI)

## Problem

Newcomers conflate the template repository’s CI with the CI that ships in the generated monorepo, leading to edits in the wrong workflow file and incorrect assumptions about what is tested where.

## User impact

Wasted time debugging CI changes; PRs that “fix CI” in one layer but not the other; confusion about ownership and expected checks.

## Proposed fix

Add explicit documentation and lightweight inline comments in both workflow files explaining which repo/context they apply to and how they relate (template-source CI validates template repo; generated CI validates consumer monorepo).

## Investigation steps

- Open both workflow files referenced by the evidence and compare triggers/jobs to identify overlapping names that cause confusion.
- Locate the first docs entrypoint(s) that mention CI and add a short diagram/section explaining the two layers and when each runs.
- Add a short comment banner at the top of each workflow noting scope and edit intent.
