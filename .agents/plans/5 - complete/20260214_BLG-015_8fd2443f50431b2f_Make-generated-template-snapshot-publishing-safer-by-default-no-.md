## Title

Make generated-template snapshot publishing safer by default (no auto-publish on push to main; require explicit publish confirmation)

## Problem

The generated monorepo template includes a snapshot publishing workflow that can run on normal `push` to `main` and executes the publisher in non-dry-run mode; once publishing secrets/env vars are present, uploads can proceed without an additional explicit confirmation gate.

## User impact

Repos generated from the template may accidentally publish externally during routine merges when secrets are configured, increasing supply-chain/release-process risk for adopters.

## Proposed fix

Change the template’s `publish-snapshots.yml` to avoid publishing on `push` to `main` by default (prefer manual dispatch/tag-based), and add an explicit confirmation gate (workflow input/approval and/or a required CLI flag like `--confirm-publish`) so uploads cannot happen by omission when credentials exist.

## Investigation steps

- Inspect `templates/monorepo-root/{{cookiecutter.repo_slug}}/.github/workflows/publish-snapshots.yml` triggers to confirm `push` to `main` is enabled by default.
- Review `tools/monorepo_publish/publish_snapshots.py` upload path to confirm publishing occurs when not `--dry-run` and credentials are present, and identify where to enforce an explicit confirmation flag.
- Decide the default-safe trigger strategy (manual-only, tag-only, or manual with required reviewers) and update the template accordingly.
- Update template docs to clearly separate dry-run/self-test usage from real publishing and describe the explicit opt-in path.

## Success criteria

- Generated repos do not perform real snapshot publishes on routine `push` to `main` by default.
- Real publishing requires an explicit opt-in gate beyond “secrets exist” (e.g., workflow input/approval and/or required `--confirm-publish`).
- Dry-run/self-test validation remains available and is documented as the safe default.
