## Title

Review Gemini credential-state log message exposure in default artifacts

## Problem

Gemini runs repeatedly emit `Loaded cached credentials.` in stderr artifacts, which may expose authentication state and adds non-actionable noise.

## User impact

Users and operators may see unnecessary auth-related logs in normal runs, complicating log hygiene and security posture.

## Proposed fix

Move credential-cache status messaging to debug-level logs or redact it from persisted stderr artifacts in default mode.

## Investigation steps

- Locate the source of the credential-cache log emission in Gemini adapter/runtime integration.
- Check current logging policy for sensitive or auth-adjacent messages.
- Implement reduced-visibility logging for this message in default runs.
- Validate that troubleshooting mode still exposes needed diagnostics when explicitly enabled.

## Success criteria

- Default persisted artifacts no longer include `Loaded cached credentials.`
- No auth-state detail is exposed in normal run stderr artifacts.
