## Title

Prevent accidental snapshot publishing from `push` to `main`

## Problem

Publishing workflow is configured to run on pushes to `main`, enabling automatic publish behavior when secrets are present.

## User impact

Routine merges can trigger unintended external package publication.

## Proposed fix

Gate publishing behind explicit manual trigger and/or protected environment approval instead of default push trigger.

## Investigation steps

- Review current workflow trigger and environment protection settings.
- Assess release process requirements for automated vs manual publish.
- Update workflow trigger logic to require explicit release intent.
- Identify publisher entry points and isolate upload invocation for testability.
- Write unit/integration tests for dry-run and missing-credential paths.
- Ensure CI runs these tests in default quality workflow.

## Success criteria

- Publish workflow does not run from ordinary pushes to `main` without explicit approval path.
- Release runbooks clearly state how live publish is intentionally initiated.
- Automated tests fail if dry-run reaches upload path.
- Automated tests fail if live publish attempts proceed without required credentials.
