## Title

Introduce `pdm run smoke` as a minimal verified path

## Problem

First successful validation currently requires users to infer which subset of checks to run.

## User impact

Onboarding is slower and users may run a full suite before proving baseline setup.

## Proposed fix

Add a dedicated `smoke` script/alias in project config that runs a narrow, stable check set and document it as first verification.

## Investigation steps

- Select the smallest meaningful test/check subset.
- Add alias in `pyproject.toml` and reference in README.
- Measure runtime and flakiness across local and CI runs.

## Success criteria

- `pdm run smoke` exists and is documented.
- `pdm run smoke` passes consistently in CI and locally on supported environments.
- Smoke runtime is materially shorter than full validation path.
